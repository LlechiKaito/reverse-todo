# Contributing Guide

> 開発参加時のルール・規約

## 書く内容

### 1. 開発フロー
- ブランチ戦略（feature ブランチ → PR → main マージ）
- PR のルール（レビュー必須、CI パス必須 等）

### 2. コーディング規約
- TypeScript strict mode
- ESLint / Prettier の設定概要
- 命名規則（ファイル名、変数名、コンポーネント名）

### 3. コミットメッセージ規約
- Conventional Commits の形式と例
- type の種類（feat, fix, refactor, docs, chore 等）

### 4. ディレクトリ規約
- Frontend: 新機能追加時のフォルダ構成ルール
- Backend: 各レイヤーに何を置くかの判断基準

### 5. レビュー観点
- レビュー時にチェックすべきポイント

## 書き方のポイント
- 新メンバーが PR を出すまでに必要な情報をまとめる
- 「なぜそのルールなのか」の理由も軽く添える
